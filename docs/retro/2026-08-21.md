### Three silent bugs in one session — this is a pattern, not an accident

All three of the following passed a fully green mocked test suite before a live run exposed
them:

1. **olbauday `observed_at` ruling.** The first implementation stamped `observed_at` from
   `gameweek_summaries.csv`'s `snapshot_time`. It passed 323 tests. It was wrong — that
   column is a stale file-generation stamp, not an observation time, and joining it would
   have handed a query for GW10 the GW38 row via `as_of()`'s own correct `WHERE observed_at
   <= ts` logic, leakage delivered by the leakage primitive doing exactly what it was built
   to do. Caught by the Architect manually reasoning against cached file content, not by any
   test.
2. **tz-aware timestamp write.** `commence_time`/`market_last_update` were written as
   genuine tz-aware datetimes. Schema validation checks column presence, not dtype, so
   nothing objected. It broke `observations()`/`as_of()` for two datasets in the *real*
   store — found only on the first authorised live capture, not in any test run before it.
3. **urllib3 debug-logger secret leak.** The application-level redaction (API key passed via
   `requests.Session.params`, never string-concatenated into a URL) was tested and green.
   It didn't matter — urllib3's own DEBUG-level logger prints the full request URL,
   `apiKey` included, entirely outside that redaction's reach. Found only when
   `--verbose` was actually run once, printing the live key to a real terminal.

Handoff lesson #6 ("tests on fresh fixtures cannot catch production bugs") already carries
three instances from session s001. This session adds three more against the *same* root
cause: a green suite built from fixtures or first-pass mocks, defeated by something that
only exists in live data, a live provider, or a live third-party library. Six instances
across two sessions is not bad luck — it's the actual failure mode of this codebase's
testing discipline so far. Recommend the Architect stop treating this as a rotating anecdote
in a numbered list and consider making one live-run verification a **standing completion
gate** for any story touching credentials, timestamps, or a provider's real response shape —
not optional, not left to whichever agent thinks to run one.

**A related but distinct seventh finding, not folded into the count above.** The
`store.write()` smuggle bug (see the update above) was *not* caught by a live external call —
it was caught by the Architect deliberately trying to break a claim the story had just
reported as proven, against a real (if temporary) `BitemporalStore`. Same family — "green
does not mean done," a boundary that held only because nobody had tried to cross it yet —
but a different mechanism: adversarial testing of a security/integrity boundary versus
mock-vs-live divergence. Worth naming separately because the fix for one (live verification
before punch-out, now a standing gate per this retro's earlier recommendation) does not cover
the other. If this recurs, the pattern to watch for is stories that claim a guarantee
("cannot be queried as observed," "cannot leak a secret") without an adversarial test that
actually tries to violate it — the four other structural guarantees shipped this session
(odds null-id, olbauday `observed_at`, the naming invariant itself) all *did* ship with a
break-first-then-fix proof; this one didn't, until the Architect supplied it after the fact.
